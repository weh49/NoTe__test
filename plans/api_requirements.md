# ThinkBoard 后端API需求文档

## 基础信息

- **基础URL**: `http://localhost:5001/api/notes`
- **数据格式**: JSON
- **字符编码**: UTF-8

---

## API接口列表

### 1. 获取所有笔记

- **方法**: GET
- **端点**: `/`
- **请求体**: 无
- **成功响应**: 
  - 状态码: 200
  - 响应体: 笔记数组
- **失败响应**: 
  - 状态码: 500

### 2. 获取单个笔记

- **方法**: GET
- **端点**: `/:id`
- **请求体**: 无
- **成功响应**: 
  - 状态码: 200
  - 响应体: 笔记对象
- **失败响应**: 
  - 状态码: 404
  - 响应体: `{"message": "Note not found"}`

### 3. 创建笔记

- **方法**: POST
- **端点**: `/`
- **请求体**: 
  ```json
  {
    "title": "String (必填)",
    "content": "String (必填)"
  }
  ```
- **成功响应**: 
  - 状态码: 201
  - 响应体: `{"message": "Note created succesfully"}`
- **失败响应**: 
  - 状态码: 400

### 4. 更新笔记

- **方法**: PUT
- **端点**: `/:id`
- **请求体**: 
  ```json
  {
    "title": "String (可选)",
    "content": "String (可选)"
  }
  ```
- **成功响应**: 
  - 状态码: 200
  - 响应体: 更新后的笔记对象
- **失败响应**: 
  - 状态码: 404

### 5. 删除笔记

- **方法**: DELETE
- **端点**: `/:id`
- **请求体**: 无
- **成功响应**: 
  - 状态码: 200
  - 响应体: `{"message": "Note deleted successfully"}`
- **失败响应**: 
  - 状态码: 404

---

## 笔记数据结构

```json
{
  "_id": "MongoDB ObjectId (24位十六进制字符串)",
  "title": "String",
  "content": "String",
  "createdAt": "Date (ISO 8601格式)",
  "updatedAt": "Date (ISO 8601格式)"
}
```

## 测试场景参考

### 正向场景
1. 获取所有笔记 - 正常返回列表
2. 创建笔记 - 使用有效标题和内容
3. 获取单个笔记 - 使用有效ID
4. 更新笔记 - 使用有效ID和数据
5. 删除笔记 - 使用有效ID

### 负向场景
1. 创建笔记 - 空标题
2. 创建笔记 - 空内容
3. 创建笔记 - 标题/内容超长
4. 获取笔记 - 无效ID格式
5. 更新笔记 - 无效ID格式
6. 删除笔记 - 无效ID格式

### 边界场景
1. 获取笔记 - 不存在的ID (全0)
2. 更新笔记 - 不存在的ID
3. 删除笔记 - 不存在的ID
