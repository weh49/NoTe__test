### BUG-001：创建笔记接口缺少空值参数校验

| 字段 | 内容 |
|------|------|
| **缺陷ID** | BUG-001 |
| **严重程度** | 高 |
| **优先级** | 高 |
| **状态** | 待修复 |
| **发现日期** | 2026-07-14 |
| **发现人** | 测试工程师 |
| **所属模块** | 笔记接口 - 创建笔记 (POST /api/notes) |

**描述**：创建笔记接口（POST /api/notes/）未对 title 和 content 字段进行空值校验。当传入空字符串时，后端依赖 Mongoose 的 `required` 校验抛出异常，进入 catch 块返回 500 错误，而非返回 400 明确告知客户端参数无效。

**复现步骤**：
1. 启动后端服务（localhost:5001）
2. 发送 POST 请求到 `/api/notes/`，请求体：`{"title": "", "content": "测试内容"}`
3. 观察响应

**预期结果**：
- 状态码：400
- 响应体：包含明确的错误消息，如 `{"message": "Title is required"}`

**实际结果**：
- 状态码：500
- 响应体：`{"message": "Internal server error"}`

**相关测试用例**：
- `test_create_invalid_data[test_data0]`（空标题）
- `test_create_invalid_data[test_data1]`（空内容）

**涉及代码**：`backend/src/controllers/notesController.js` 第32-43行

### BUG-002：创建笔记接口缺少字段长度校验

| 字段 | 内容 |
|------|------|
| **缺陷ID** | BUG-002 |
| **严重程度** | 中 |
| **优先级** | 中 |
| **状态** | 待修复 |
| **发现日期** | 2026-07-14 |
| **发现人** | 测试工程师 |
| **所属模块** | 笔记接口 - 创建笔记 (POST /api/notes) |

**描述**：创建笔记接口（POST /api/notes/）未对 title 和 content 字段进行长度校验。后端 Model 层（Note.js）仅设置 `required: true`，未设置 `maxlength`。传入超长字符串时仍能创建成功。

**复现步骤**：
1. 启动后端服务（localhost:5001）
2. 发送 POST 请求到 `/api/notes/`，请求体：`{"title": "正常标题", "content": "a" * 10000}`
3. 观察响应

**预期结果**：
- 状态码：400
- 响应体：包含明确的错误消息，如 `{"message": "Content exceeds maximum length"}`

**实际结果**：
- 状态码：201
- 响应体：`{"message": "Note created succesfully"}`

**相关测试用例**：
- `test_create_invalid_data[test_data6]`（超长标题）
- `test_create_invalid_data[test_data7]`（超长内容）
- `test_create_note_base_data`（边界值超限数据）

**涉及代码**：`backend/src/models/Note.js` 第6-17行

### BUG-003：错误响应码不区分客户端错误和服务端错误

| 字段 | 内容 |
|------|------|
| **缺陷ID** | BUG-003 |
| **严重程度** | 中 |
| **优先级** | 中 |
| **状态** | 待修复 |
| **发现日期** | 2026-07-14 |
| **发现人** | 测试工程师 |
| **所属模块** | 笔记接口 - 全部接口 |

**描述**：所有接口的 catch 块统一返回 500（服务端错误），未区分客户端输入错误（400）和服务端内部错误（500）。这会导致客户端无法根据状态码判断是自身参数问题还是服务器故障。

**复现步骤**：
1. 发送任意无效请求（如空标题创建笔记）
2. 观察返回的状态码

**预期结果**：
- 客户端参数错误：返回 400
- 服务端内部错误：返回 500

**实际结果**：
- 所有错误统一返回 500

**相关测试用例**：全部负向测试用例

**涉及代码**：`backend/src/controllers/notesController.js` 全部 catch 块

### BUG-004：创建笔记接口响应未返回笔记 ID

| 字段 | 内容 |
|------|------|
| **缺陷ID** | BUG-004 |
| **严重程度** | 中 |
| **优先级** | 中 |
| **状态** | 待修复 |
| **发现日期** | 2026-07-16 |
| **发现人** | 测试工程师 |
| **所属模块** | 笔记接口 - 创建笔记 (POST /api/notes) |

**描述**：创建笔记接口（POST /api/notes/）成功后仅返回 `{"message": "Note created succesfully"}`，未返回新创建笔记的 `_id`。这导致客户端无法直接获取资源 ID 进行后续操作（如查询、更新、删除），必须额外调用 GET 列表接口间接获取，增加了不必要的网络开销和竞态风险。

**复现步骤**：
1. 发送 POST 请求到 `/api/notes/`，请求体：`{"title": "测试", "content": "内容"}`
2. 检查响应体是否包含 `_id` 字段

**预期结果**：
- 状态码：201
- 响应体：`{"message": "Note created succesfully", "data": {"_id": "...", "title": "测试", "content": "内容"}}`

**实际结果**：
- 状态码：201
- 响应体：`{"message": "Note created succesfully"}`（无 `_id`）

**相关测试用例**：`conftest.py` 的 `create_and_cleanup_note` fixture（需二次查询列表获取 ID）

**涉及代码**：`backend/src/controllers/notesController.js` 第38行

### BUG-005：获取单个笔记接口未拦截空 ID，路由匹配到列表接口

| 字段 | 内容 |
|------|------|
| **缺陷ID** | BUG-005 |
| **严重程度** | 中 |
| **优先级** | 中 |
| **状态** | 待修复 |
| **发现日期** | 2026-07-16 |
| **发现人** | 测试工程师 |
| **所属模块** | 笔记接口 - 获取单个笔记 (GET /api/notes/:id) |

**描述**：当请求 URL 为 `GET /api/notes/`（即 `:id` 为空字符串）时，Express 路由将其匹配到获取列表的 `GET /api/notes/` 路由，而非拒绝请求。这导致空 ID 请求意外返回 200 和全部笔记列表，而非 400 参数错误。

**复现步骤**：
1. 发送 GET 请求到 `/api/notes/`（末尾不带任何 ID）
2. 观察返回的状态码和响应体

**预期结果**：
- 状态码：400
- 响应体：`{"message": "Note ID is required"}`

**实际结果**：
- 状态码：200
- 响应体：全部笔记列表数组

**相关测试用例**：`test_get_note_id_boundary[空ID]`（xfail 标记）

**涉及代码**：`backend/src/routes/notesRoutes.js`（路由定义顺序，`/` 与 `/:id` 未做空值区分）
